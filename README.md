# เช็คน้ำท่วม กรุงเทพฯ และปริมณฑล

เว็บแอปดูสถานการณ์น้ำท่วม ประกอบด้วยหน้าแผนที่ ภาพรวมสถานการณ์ รายการจุดท่วมพร้อมกราฟย้อนหลัง เช็คเส้นทางตามประเภทรถ จุดติดตามพร้อมแจ้งเตือน และรายงานน้ำท่วมจากผู้ใช้ ไม่ต้องมีขั้นตอน build เป็นไฟล์ HTML, CSS และ JavaScript ล้วน (ไลบรารีแผนที่ Leaflet รวมอยู่ในโฟลเดอร์ `vendor/` แล้ว)

**สถานะปัจจุบัน:** ข้อมูลที่แถมมาใน `data/flood.json` เป็นข้อมูลตัวอย่างสมมติทั้งหมด (`"mode": "sample"`) หน้าเว็บจะแสดงป้าย "ข้อมูลตัวอย่าง" ให้เห็นชัด ต้องต่อข้อมูลจริงตามหัวข้อ 4 ก่อนเปิดให้คนใช้ตัดสินใจเดินทาง

## 1. โครงสร้างไฟล์

```
index.html            หน้าเว็บ
css/app.css           สไตล์ (สีและธีมอยู่ที่ตัวแปรบนสุดของไฟล์)
js/config.js          ตั้งค่าทั้งหมด แก้ไฟล์นี้ไฟล์เดียวเมื่อย้ายไปโฮสต์เอง
js/*.js               data, map, charts, route, watch, reports, app
data/flood.json       ข้อมูลน้ำท่วมที่หน้าเว็บอ่าน (ตอนนี้เป็นตัวอย่าง)
functions/api/        API รายงานจากผู้ใช้ (Cloudflare Pages Functions)
tools/                สคริปต์สร้างข้อมูลตัวอย่างและดึงข้อมูลจริง
.github/workflows/    ตั้งเวลาอัปเดตข้อมูลอัตโนมัติทุก 30 นาที
vendor/               Leaflet และ markercluster (ใส่ไว้ในชุดแล้ว)
```

## 2. ลองในเครื่อง

ต้องเปิดผ่านเซิร์ฟเวอร์ ห้ามดับเบิลคลิกไฟล์ `index.html` เพราะเบราว์เซอร์จะไม่ยอมให้อ่าน `data/flood.json`

```
cd flood-monitor
python3 -m http.server 8000
```

แล้วเปิด `http://localhost:8000` ถ้าเปิดเป็น `http://localhost:8000/?demo=1` ระดับน้ำจะขึ้นลงเองทุก 8 วินาที ใช้ลองระบบแจ้งเตือนและกราฟได้ ในเครื่องจะยังไม่มี API รายงาน ระบบจึงเก็บรายงานไว้เฉพาะในเบราว์เซอร์นั้น (มีข้อความบอกในฟอร์ม)

## 3. เปิดให้คนทั่วไปใช้ (Cloudflare Pages)

1. สร้างบัญชี Cloudflare แล้วไปที่ Workers & Pages > Create > Pages
2. เลือกอัปโหลดโฟลเดอร์นี้ตรงๆ หรือเชื่อมกับ GitHub repo (ช่อง build command เว้นว่าง, output directory ใส่ `/` หรือเว้นว่าง)
3. จะได้ลิงก์ `ชื่อโปรเจกต์.pages.dev` ผูกโดเมนของตัวเองได้ภายหลัง
4. เปิดระบบรายงานจากผู้ใช้ (ถ้าต้องการ)
   - Workers & Pages > KV > Create namespace ตั้งชื่อ `flood-reports`
   - โปรเจกต์ Pages > Settings > Bindings (หรือ Functions) > เพิ่ม KV namespace โดยตั้งชื่อตัวแปรเป็น `REPORTS` เลือก namespace ที่สร้างไว้
   - Settings > Variables เพิ่ม `SALT` เป็นข้อความสุ่มยาวๆ (ใช้แฮช IP ก่อนเก็บ) และ `REPORT_TTL_HOURS` ถ้าจะเปลี่ยนจาก 6 ชม.
   - Deploy ใหม่ 1 ครั้ง
5. ถ้าใช้ Netlify, Vercel หรือ GitHub Pages: หน้าเว็บใช้ได้ปกติ แต่โฟลเดอร์ `functions/` ใช้ไม่ได้ ให้ตั้ง `reportsApi: ''` ใน `js/config.js` (รายงานจะเก็บเฉพาะในเครื่องผู้ใช้) หรือเขียน API ที่หน้าที่เดียวกันบนบริการนั้น โดยใช้รูปแบบข้อมูลตามไฟล์ `functions/api/[[path]].js`

## 3ก. ขึ้นด้วย GitHub + Render (ทางที่เร็วที่สุดถ้ามีบัญชีสองที่นี้แล้ว)

1. GitHub: สร้าง repo ใหม่ (เลือก Public ถ้าจะใช้ข้อมูลอัตโนมัติตามหัวข้อ 4) กด "uploading an existing file" แล้วลากไฟล์ทั้งหมดในโฟลเดอร์ `flood-monitor` (หลังแตก zip) เข้าไป รวมโฟลเดอร์ซ่อน `.github` ด้วย ถ้าลากโฟลเดอร์ซ่อนไม่ได้ ให้ใช้ GitHub Desktop หรือคำสั่ง git แทน
2. Render: New > Static Site > เลือก repo นั้น ช่อง Build Command เว้นว่าง Publish Directory ใส่ `.` แล้วกด Create (หรือใช้ New > Blueprint ชี้ไปที่ `render.yaml` ในชุด)
3. ได้ลิงก์ `ชื่อ.onrender.com` ส่งให้คนอื่นใช้ได้ทันที เมื่อแก้ไฟล์ใน GitHub Render จะอัปเดตเว็บให้เอง

ข้อจำกัดของ Render Static Site: ไม่รัน API ในโฟลเดอร์ `functions/` (ของ Cloudflare) ระบบรายงานจากผู้ใช้จึงจะเก็บเฉพาะในเครื่องของแต่ละคน (แอปสลับโหมดเองและแจ้งไว้ในฟอร์ม) ถ้าต้องการให้ทุกคนเห็นรายงานร่วมกัน ให้ใช้ Cloudflare Pages ตามหัวข้อ 3 หรือเพิ่มเซิร์ฟเวอร์เล็กๆ บน Render พร้อมฐานข้อมูล

## 4. ต่อข้อมูลจริง

หน้าเว็บอ่านไฟล์เดียวคือ `data/flood.json` (ตั้งที่อยู่ใน `js/config.js` ช่อง `dataUrl` ใส่ URL เต็มได้) รูปแบบไฟล์:

```
{
  "meta": {
    "mode": "live",                     // "sample" จะขึ้นป้ายข้อมูลตัวอย่าง
    "updatedAt": "2026-09-26T03:00:00Z",
    "historyStepMin": 30,               // ระยะห่างของแต่ละค่าใน history (นาที)
    "sources": [{ "id": "team", "name": "ตารางบันทึกจากทีมงาน", "status": "ok", "fetchedAt": "..." }]
  },
  "nodes": [{ "id": "asok", "name": "อโศก", "lat": 13.735, "lon": 100.565, "province": "กทม.", "major": false }],
  "segments": [{
    "id": "e8", "road": "ถ.สุขุมวิท", "from": "asok", "to": "onnut",
    "depth": 6,                         // ซม. ณ ตอนนี้
    "trend": "down",                    // up | flat | down
    "updatedAt": "2026-09-26T02:55:00Z",
    "source": "team",
    "history": [3, 4, 6, 6],            // เก่า -> ใหม่ ค่าสุดท้ายคือค่าปัจจุบัน
    "geometry": [[13.735, 100.565], [13.70, 100.60]]   // ไม่บังคับ แนวถนนจริง (lat, lon)
  }]
}
```

**วิธี A: ตารางบันทึกจากทีมงาน (ใช้ได้ทันที)**
ทีมงานหรือจุดรับซื้อกรอกระดับน้ำใน Google Sheets คอลัมน์ `segment_id, depth_cm, observed_at, note` (ดูตัวอย่างที่ `tools/observations.example.csv`) แล้วเลือก File > Share > Publish to web > CSV จากนั้น

1. เก็บโฟลเดอร์นี้ไว้ใน GitHub repo สาธารณะ
2. ตั้ง Secret ชื่อ `OBS_CSV_URL` เป็นลิงก์ CSV ที่เผยแพร่
3. เปิด Actions ให้ workflow `update-flood-data` ทำงาน มันจะรัน `tools/fetch_data.py` ทุก 30 นาที สะสมประวัติ 24 ชม. และเผยแพร่ไฟล์ไปที่บรานช์ `data`
4. ตั้ง `dataUrl` ใน `js/config.js` เป็น `https://raw.githubusercontent.com/<ผู้ใช้>/<repo>/data/flood.json`

ทดลองในเครื่องได้ด้วย `cp tools/observations.example.csv tools/observations.csv && python3 tools/fetch_data.py` (ไฟล์ `data/flood.json` จะถูกเขียนทับ ถ้าอยากได้ตัวอย่างกลับมา ให้รัน `python3 tools/make_sample.py`)

**วิธี B: ข้อมูลทางการ** (สำนักการระบายน้ำ กทม., ThaiWater, GISTDA)
ฟังก์ชัน `fetch_official()` ใน `tools/fetch_data.py` เป็นจุดต่อที่ยังว่างอยู่ ต้องตรวจก่อนว่าแต่ละแหล่งเปิดให้โปรแกรมดึงข้อมูลได้หรือไม่ และเงื่อนไขการนำข้อมูลไปเผยแพร่ต่อเป็นอย่างไร แล้วเขียนตัวแปลงให้คืนรายการ `segment_id, depth_cm, observed_at` โดยกำหนดเองว่าสถานีวัดแต่ละแห่งตรงกับช่วงถนนใด

**ปรับโครงข่ายถนน**
แก้ `tools/network.json` (จุดเชื่อมและช่วงถนน) ตัวอย่างที่แถมมาใช้เส้นตรงเชื่อมระหว่างจุดเชื่อม ซึ่งยังไม่ตรงกับแนวถนนจริง ให้ใส่ `geometry` ของแต่ละช่วง (จุดพิกัดตามแนวถนน) เพื่อให้เส้นบนแผนที่และระยะทางตรงกับความจริง

## 5. แผนที่พื้นหลัง

ค่าเริ่มต้นใช้ไทล์ของ OpenStreetMap ซึ่งมีข้อกำหนดการใช้งานที่ไม่รองรับผู้ใช้จำนวนมาก ถ้าเปิดให้คนทั่วไปใช้ ให้สมัครผู้ให้บริการไทล์ (เช่น MapTiler, Stadia Maps, Thunderforest) แล้วแก้ `tiles.url` และ `tiles.attribution` ใน `js/config.js` ตามที่ผู้ให้บริการกำหนด ต้องคงข้อความให้เครดิตแหล่งที่มาไว้

## 6. รายงานจากผู้ใช้

- ผู้ใช้กดปุ่ม "รายงานน้ำท่วม" เลือกตำแหน่ง ระดับน้ำ (ข้อเท้า, น่อง, เข่า ฯลฯ) และข้อความสั้นๆ
- รายงานแสดงนาน 6 ชม. แล้วหายเอง มีสถานะ "ยังไม่ยืนยัน" จนกว่าจะมีคนอื่นกดยืนยันครบ 2 คน (ตั้งได้ที่ `reportsConfirmNeeded`)
- รายงานไม่ถูกนำไปรวมกับข้อมูลระดับน้ำทางการ แต่ระบบเส้นทางจะเตือนถ้ามีรายงานอยู่ใกล้เส้นทางไม่เกิน 300 ม.
- การป้องกันการใช้ในทางที่ผิดเป็นแบบพื้นฐาน (จำกัด 6 ครั้งต่อ 10 นาทีต่อ IP, ตรวจขอบเขตพิกัด, ตัดข้อความ, ไม่เก็บ IP ตรงๆ) ถ้าเปิดใช้จริงกับคนจำนวนมาก ควรเพิ่ม Cloudflare Turnstile และหน้าคัดกรองรายงาน

## 7. การแจ้งเตือน

จุดติดตามเก็บไว้ในเบราว์เซอร์ของผู้ใช้เท่านั้น ระบบตรวจเมื่อข้อมูลอัปเดต (ทุก 2 นาที) และเด้งข้อความเตือนเมื่อน้ำในรัศมีสูงถึงระดับที่ตั้งไว้ หรือแย่ลง **ทำงานเฉพาะตอนที่เปิดหน้านี้ค้างไว้** ยังไม่มีการส่งเตือนเมื่อปิดหน้า ถ้าต้องการต้องเพิ่ม Web Push หรือส่งข้อความผ่านเซิร์ฟเวอร์ (เช่น LINE Messaging API) ซึ่งต้องมีที่เก็บข้อมูลผู้ติดตามฝั่งเซิร์ฟเวอร์เพิ่ม

## 8. ปรับแต่ง

ที่ `js/config.js`: ความถี่รีเฟรช, อายุข้อมูลที่ถือว่าเก่า, เกณฑ์ระดับน้ำทั้ง 4 ระดับ (`thresholds`), ความสูงน้ำที่รถแต่ละประเภทผ่านได้ (`vehicles`), ลิงก์แหล่งข้อมูลทางการที่แสดงท้ายหน้า, พิกัดกึ่งกลางแผนที่ ค่าความสูงน้ำของรถเป็นค่าประมาณทั่วไป ควรปรับตามรถที่ใช้จริง

## 9. ข้อจำกัดที่ควรรู้

- ข้อมูลเริ่มต้นเป็นข้อมูลสมมติ และแอปไม่ใช่ประกาศทางการ
- ตัวคำนวณเส้นทางใช้เฉพาะถนนสายหลักที่มีข้อมูลระดับน้ำ ไม่ใช่การนำทางเต็มรูปแบบ มีปุ่มเปิดต่อใน Google Maps สำหรับซอยและการจราจรจริง
- ทดสอบตรรกะของ API รายงานกับ KV จำลองในเครื่องแล้ว แต่ยังไม่ได้ทดสอบบน Cloudflare จริง
- ยังไม่ได้ทดสอบกับข้อมูลจริงจากหน่วยงานใดๆ
- ยังไม่มีการเก็บสถิติการใช้งานหรือบัญชีผู้ใช้
